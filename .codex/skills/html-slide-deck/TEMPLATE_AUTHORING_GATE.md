# Template Authoring Gate

新しいテンプレートやサンプルを作る前に通す必須ゲートです。

## 目的

テンプレート作成時に一般的な箱図やカードUIへ流れることを防ぎます。
OWS参照PDFをデザイン言語の一次参照として扱い、承認済みテンプレートとの差分を最小にします。

## 必須手順

1. 参照PDFから近いページを1枚選びます。
   - 同格要素なら4特徴ページを基準にします。
   - 仕様一覧ならAPI仕様ページを基準にします。
   - 変更前後なら既存資産との関係ページを基準にします。
   - 時系列なら処理フローページを基準にします。
   - 境界なら信頼境界ページを基準にします。
2. 参照ページの構図を先に写します。
   - 見出し階層を写します。
   - 線幅を写します。
   - 余白を写します。
   - 境界表現を写します。
   - 情報密度を写します。
3. 内容だけをプレースホルダーへ置き換えます。
   - 見た目の変更を同時に行いません。
4. 承認済みテンプレートを1つ以上横に並べます。
   - Page外枠が揃っているか確認します。
   - タイトル処理が揃っているか確認します。
   - Content Regionの使い方が揃っているか確認します。
5. 新規テンプレートを画像として確認します。
   - HTMLの存在だけで完成扱いしません。
6. Reference Gateを通過したものだけを正式追加します。
   - `template.html`を追加します。
   - `example.html`を追加します。
   - `README.md`を追加します。

## 不合格条件

- 参照PDFにないHub図を作る。
- 参照PDFにない放射状Network図を作る。
- 色付きカードを並べる。
- Node上部へ太い色帯を付ける。
- 角丸を付ける。
- 影を付ける。
- 斜め線を多用する。
- 文字を小さくして押し込む。
- 見出しに読点を入れる。
- PageとCompositionとDiagramを混ぜる。
- 参照PDFと横並び比較しない。

## 優先する母型

```text
同格要素       4特徴ページ
仕様一覧       API仕様ページ
変更前後       既存資産との関係ページ
境界整理       信頼境界ページ
時系列整理     処理フローページ
```

## 完成条件

完成条件は情報が読めることではありません。
参照PDFの別ページとして混ぜた時に違和感が少ないことです。
